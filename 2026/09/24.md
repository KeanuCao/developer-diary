今天整理了桌面应用的设计哲学
🏗️ 核心架构与设计原则（AI 强制执行）
本项目致力于达到商业级桌面应用标准。在编写任何代码时，必须严格遵守以下 5 大核心原则，违反任何一条均视为架构违规：

1. 开闭原则 (OCP) 与 插件化路由
   - 核心路由（如 `MainWindow`, `EditorArea`）严禁修改以支持新文件类型。
   - 新增文件类型必须通过实现 `IEditorFactory` 并注册到单例 `EditorRegistry` 完成。

2. UI 框架隔离 (MVVM) 与 信号槽通信
   - 纯净底层：`src/services/`, `src/core/` 等非 UI 层严禁 `import PyQt5`，必须保持 Pure Python。
   - 零直接引用：组件间严禁直接持有引用或调用方法。所有跨组件交互必须通过 `pyqtSignal` 和 Slot 实现。如需跨层通信，必须在 `src/app/` 适配层将回调转为信号。

3. 跨平台兼容与工程标准化
   - 跨平台底线：路径拼接必须使用 `os.path.join()`，严禁硬编码 `/` 或 `\`；用户目录必须通过 `os.path.expanduser("~")` 获取。
   - 生命周期标准化：所有编辑器组件必须继承 `BaseEditorWidget`，严格实现其定义的生命周期接口，严禁遗漏 `super().__init__()`。

4. 克制即高级 (产品与交互设计约束)
   - 内容优先：严禁使用粗重边框和过度装饰，必须通过留白和浅阴影构建 UI 层级。
   - 显式化交互：拖拽、连线等复杂交互必须提供明确的视觉引导（高亮、辅助线），严禁模糊吸附。
   - 渐进式披露：复杂属性面板必须默认折叠高级选项，严禁一屏堆砌所有控件。

5. 核心概念对齐与单一真相源 (Concept-Driven & Single Source of Truth)
   - 唯一真相源：`docs/concept-evolution.md` 是 v1.0 产品的唯一顶层真相源，所有下游设计、任务拆分和编码实现必须以它为准。
   - 概念强制对齐：所有 UI 交互、数据模型和路由设计，必须严格符合核心概念定义（例如：`.bot` 是逻辑中枢，`.case` 是原子步骤；Release 模式下 UI 必须物理锁定）。
   - 冲突熔断机制：在编码或设计前，必须核对核心概念。若发现实现与概念文档冲突，严禁在代码中“灵活处理”或“打补丁”，必须立即终止当前工作并报告，要求先更新概念文档。
