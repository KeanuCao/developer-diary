## 一、初心

我不是单纯想找一份工作。

我做了二十多年软件工程，在 Cisco 待了十七年，经历过全球级生产环境，也带过跨技术栈团队。到了这个阶段，我想要的不是“再写几年代码”，而是做出真正被看见、被使用、能证明我判断力的东西。

我想加入 DeepSeek，或者说，想让自己具备加入 DeepSeek 的能力。DeepSeek Harness 这个方向吸引我，因为它做的是代码智能体，是我每天在用、也真正在意的东西。我希望有一天，别人看我的简历，不只是看到“24 年经验”，而是看到：这个人深度使用 Claude Code，理解 Agent 工作流，并且为 dsh 生态做出了具体贡献。

这就是我的初心：**用工程作品，而不是用简历，证明我的价值。**

## 二、现实问题

但现实很清楚。

第一，我已经在空窗期了。这件事无法改变，回头没有意义，只能把这段时间变成可展示的工程证据。

第二，年龄是硬门槛。海投基本无效，HR 的第一道筛选就会把我挡掉。能走的路只有内推、猎头、远程、顾问，以及让作品主动出现在别人视野里。

第三，我的精力有限。我不可能同时学 TypeScript、重写项目、做开源、投简历、维持现金流。必须选一条主线，一条副线。

第四，Claude Code 是我的主力生产工具，而且我非常满意。dsh 虽然开源，但是它主推 Web 界面，不符合我的极客习惯。我下不去口，这不是矫情，是真实体验。

第五，dsh 社区还早。它鼓励插件，鼓励生态，鼓励博客和讨论，但核心仓库不开放 PR。这意味着我不能走“修核心 bug 被看见”的路线。

## 三、解决方案

我决定把问题拆成两个目录，两条线。

**主力目录：Claude Code 项目。**
这里继续用 Claude Code 开发，目标是推进项目本身的功能、修 bug、迭代版本。这是主线，占我 70% 到 80% 的精力。它是我求职的基本盘，也是我每天真实使用的“Claude Code 体验实验室”。

**dsh 实验场：从主力项目 clone 一份。**
这个目录不推进项目功能，只做一件事：用 dsh CLI / TUI 跑真实任务。不是玩具任务，是我本来就要做的小任务。在过程中记录卡点：哪些操作在 Claude Code 里是肌肉记忆，到了 dsh 里就卡住；哪些反馈缺失；哪些配置迁移不完整。

然后，只选一个卡点，做一个最小插件。不追求完整，不追求架构，只追求能跑、能解决我自己的具体问题。发布到 GitHub，加 `dsh-plugin` 话题，写一篇短文说明设计决策。再去 dsh 的 GitHub Discussions 里，以 Claude Code 重度用户的身份分享观察。

我不再试图让 dsh 变成 Claude Code。我只做一件事：**把 Claude Code 给我的手感，变成 dsh 生态里可复用的插件。**

插件方向已经清晰：CLI 下的上下文压缩体验、终端里的跨文件 diff 展示、Claude Code 配置迁移、插件发现与安装体验。选一个最有痛感的，做最小版本。

## 四、今日决定

本周：安装 dsh TUI，clone 主力项目到实验场，用 dsh 跑两到三个真实任务，记录三个最别扭的卡点。

同时，每周联系三个前同事或行业人脉，不说“我在空窗”，说“我在 dsh 生态做插件，你们团队有没有类似需求”。保持现金流，保持交付状态。
