你遇到的这个问题，核心原因在于 `.sbxenv.yaml` 里**没有声明 `workspace` 字段**，导致 Claude Code 在一个空的沙箱内置目录里启动，自然看不到你宿主机上的 `CLAUDE.md`。

### 🔍 问题根源：工作区未被挂载

根据 Docker 官方文档，当环境文件**未指定 `workspace` 字段**时，`sbx` 会创建一个 **“无挂载（mountless）”** 的沙箱。这意味着：

- 你的宿主机目录 `C:\wp-sbx\job-tracker` **完全没有被挂载**进沙箱。
- Claude Code 在沙箱内使用的是模板镜像默认的工作目录 `/home/agent/workspace`。
- 这个默认目录是**沙箱内部的空目录**，与你的宿主机文件无关。因此，放在 `C:\wp-sbx\job-tracker` 下的 `CLAUDE.md` 对沙箱内的 Claude 来说是不存在的。

### 🛠️ 解决方案：在环境文件中声明工作区

你需要在 `.sbxenv.yaml` 中显式添加 `workspace` 字段，告诉 `sbx` 把哪个宿主机目录挂载进去。

**修改你的 `.sbxenv.yaml` 文件：**
```yaml
schemaVersion: "1"
name: job-tracker
agent: claude
workspace: .          # 新增这一行，挂载环境文件所在目录
env:
  ANTHROPIC_BASE_URL: "https://api.deepseek.com/anthropic"
  ANTHROPIC_MODEL: "deepseek-flash[1m]"
```
`workspace: .` 的含义是：**挂载包含该环境文件的目录**（即 `C:\wp-sbx\job-tracker`）到沙箱内。这样你的 `CLAUDE.md` 和所有项目文件都会出现在沙箱的工作区里。

### ⚠️ 关键：必须删除旧沙箱后重建

**工作区配置在沙箱创建时即固定，后续修改环境文件不会影响已存在的沙箱**。所以你之前的 `job-tracker` 沙箱仍然是无挂载状态，仅仅修改文件是不够的。

执行以下命令，**强制删除旧沙箱**，然后用新配置重建：

```powershell
# 1. 删除旧的、配置错误的沙箱
sbx rm --force job-tracker

# 2. 重新启动
sbx env run
```

`sbx env run` 会检测到旧的沙箱已不存在，从而根据新的 `.sbxenv.yaml` 创建一个**带正确工作区挂载**的新沙箱。

### ✅ 验证挂载是否成功

重建后，在 Claude Code 界面里用 `!` 前缀执行 shell 命令来确认：

```
!pwd
!ls
!cat CLAUDE.md
```
如果一切正常，`pwd` 应该显示 `/home/agent/workspace`，`ls` 会列出你的项目文件，`cat CLAUDE.md` 则能打印出你写入的指令内容。

### 📌 关于 CLAUDE.md 位置的补充

Claude Code 只读取其**工作目录根目录**下的 `CLAUDE.md`，不会向下递归查找子目录。你的文件直接位于 `C:\wp-sbx\job-tracker` 根下，与 `workspace: .` 映射后的沙箱工作区根目录是对应的，位置正确。
